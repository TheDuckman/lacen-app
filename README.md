# Repo structure

## The "lacen-base-files" folder

In here we have the files required to generate the `lacen-base` image.

The Dockerfile inside this folder will use an Ubuntu (focal fossa - 20.04) base layer and do a bunch of stuff on top of it:

- Upgrade and update apt
- Install packages and libs required by the R packages
- Add some repos to install R, Yarn and NodeJs
- Install R (version 4.1.2-1.2004.0), NodeJs (v 16.15.0) and Yarn
- Install the R packages required to run the application using the 'installpackages.R' script.

That last step can sometimes fail partially due to internet issues or packages that depend on other packages. When that happens, we try to manually add the dependencies to the `installpackages.R` to make sure all the packages are installed correctly, otherwise the LACEN application won't work.

inside the lacen-base folder are the files required to create the docker image that will serve as the foundation of the application.

The `build.sh` script will run all the commands to build and upload the docker image to dockerhub.

## The "back" folder

In here we have the source code for the application's backend. There is another Dockerfile here to build the `lacen-app` image, which contains a NodeJs web server that instanciates a persistent R process that will act as our R server.

We also have another `build.sh` to run the commands to generate the `lacen-app` docker image and push it to docker hub.

The Dockerfile uses the `lacen-base` as a primer and then proceeds to install the node modules (js packages) that the backend requires. Some user/group creation and configuration is done and the required folders are set up inside the image. A bunch of files are copied in the process too.

When the container is run, a NodeJs web server is fired up. The HTTP server starts listening to incoming requests at the designated port and a socket server is also initiated.

# Deploy configuration

## Nginx configuration

Inside the host VM we must have the Nginx web server installed and configured. The application should work with other types of web servers (such as Apache Tomcat) but in this documentation we will cover only the Nginx configuration.

Let's assume you have a domain like _lacen.ml_. In your DNS records you should have a 'type A' record that points to your VM.

Once you have a domain with a DNS record that points to your VM, you'll now have to create somes files inside `/etc/nginx` (we will use _lacen.ml_ as domain for this example):

```
/etc/nginx/sites-available/lacen.ml
```

The contents of this file should be:

```
server {
	server_name lacen.ml;

	root $PATH_TO_FRONTEND_FOLDER;

	location /api/ {
    rewrite ^/api(.*) $1 break;
    proxy_pass http://localhost:3000;
  }

	location / {
		try_files $uri $uri/ =404;
#		proxy_pass http://localhost:8080;
	}
}
```

where $PATH_TO_FRONTEND_FOLDER is the path to the folder where the files generated by `yarn build` on the `front` folder of the repo are located (i.e. /home/ubuntu/lacen/front or something like that).

```
/etc/nginx/sites-enabled/lacen.ml
```

## Application structure

The application's folder structure should be as follows:

```
├── lacen/
│   ├── nginx/
│   │   ├── default.conf
│   ├── front/
│   │   ├── <frontend files>
│   ├── docker-compose.yml
│   ├── saved-files/
```

## The `saved-files` folder

This folder wil be used to easily exchange files between the backend container and the user. All the images that the R scripts generate will be placed here.

In order for this to work properly the folder should be configured with specific ownership and permission settings: the owner should be _www-data:www-data_ and the permission _777_. This will allow the `node` service (backend) to write files to this folder from inside the container.

## docker-compose.yml file

In this file we have 2 services:

- `node`: this is the backend of the application. In this section of the docker-compose.yml file we need to configure the **port** that the container will expose (and that will enable access to our API), a **volume (bind mount)**, where the images generated by the R script will be saved, and the **env file** that will set some environment variables.

- `nginx`: this is the proxy server that will be responsible for serving the frontend of the application. In this section of the docker-compose.yml file we need to configure the **port** that the container will expose and the **volumes** so we can point to the main frontend folder (./front) and the configuration file for the Nginx server (inside ./nginx)

The `docker-compose.yml` file should be located alongside a **front** folder (where the frontend files will be), a **nginx** folder (containing a `default.conf` file), a `lacen.env` file, containing the environment variables for the application, and a `saved-files` folder with some specific ownership and permission settings, for ease of access: the owner should be _www-data:www-data_ and the permission _777_. This will allow the `node` service to write files to this folder from inside the container.

## Dev env

To be able to run the application locally you'll need:

- The `lacen-base` container running
- The front end running, in dev mode
- The backend running, in dev mode
